# 第二阶段路线图：AI 智能分析

第一版用可靠的规则回答了“**发生了什么变化**”。第二阶段的目标是帮助回答另外两个问题：
“**为什么重要**”和“**接下来应该做什么**”。

## 原则

1. **AI 是增强，不是前提**：没有 API Key 时，所有第一版功能照常工作；AI 结果作为附加字段（如 `event.ai`），可以随时关闭。
2. **付费与密钥先确认**：任何调用付费 API 的功能默认关闭，开启前需要你明确同意；Key 只存放在 GitHub Actions Secrets，绝不进入前端或仓库。
3. **可追溯、不编造**：AI 只能基于引擎提取的原文片段生成内容，输出中必须引用来源字段；无法从原文得出的结论标记为“推测”。招聘、截止日期等事实字段仍以规则提取的结果为准。
4. **成本可控**：只对评分达到阈值的新变化调用；按事件 ID 缓存结果，不重复分析；单次运行设置调用上限与 token 预算。

## 计划功能

| 阶段 | 功能 | 说明 |
| --- | --- | --- |
| 2.1 | 情报摘要与“为什么重要” | 对高分事件生成 2–3 句中文摘要和与用户关注点的关联说明 |
| 2.2 | 行动建议 | 例如“截止前 7 天提交申请”“升级到 x.y 以修复安全问题”，附原文依据 |
| 2.3 | 语义去重与聚类 | 识别不同来源对同一事件的报道，合并为一张卡片 |
| 2.4 | 个性化日报 | 基于每日摘要生成一段可读的简报，可通过 Issue / 邮件发送 |
| 2.5 | 自然语言规则 | “只告诉我北京的大模型实习” → 自动生成关键词与过滤条件（仍以可解释规则执行） |
| 2.6 | 网页选择器助手 | 粘贴网址，AI 推荐稳定的 CSS 选择器，由你确认后写入配置 |

## 其他后续扩展（非 AI）

- 更高频率检查（每 6 小时 / 每小时）：`frequency` 字段已预留；需要按来源分组调度。
- 邮件（SMTP）、Telegram Bot、企业微信机器人通知；微信相关接口仅在确认官方允许且具备权限后开发。
- 私密配置：私有仓库 + 加密数据，或可选的轻量后端。
- JavaScript 渲染页面：可选 Playwright 抓取（需评估资源消耗与站点条款）。
- 信息源模板库：常见高校、招聘平台、官方机构的选择器模板。

## v0.3 候选（基于 v0.2 的实际使用）

1. **更多结构化招聘来源**：寻找使用 Greenhouse / Lever / SmartRecruiters / Workable 等提供官方公开 API 的制造业、物流企业；每个都先用 Probe 工作流验证。
2. **职位详情补全（可选）**：对命中筛选的少量职位抓取详情页，补充学历、届别与截止日期（需控制请求频率并逐站确认 robots）。
3. **个人订阅视图**：把招聘雷达的筛选条件保存为多个“订阅”，并在每日摘要中按订阅分组。
4. **邮件 / Telegram 通知**：通过 Actions Secrets 配置，默认关闭。
